# กฎการทำงานร่วมกัน & Git Workflow (Rules of Engagement)

เอกสารฉบับนี้คือ "ข้อตกลงร่วมกัน" ระหว่างนักพัฒนา (คุณ) และผู้ช่วย AI (ผม) เพื่อให้การทำงานมีมาตรฐานระดับมืออาชีพ ปลอดภัย และไม่เกิดข้อผิดพลาดสะสมครับ

---

## 🛑 1. กฎการตรวจสอบหลังจบเฟส (Interactive Checkpoints)

เพื่อป้องกันการเขียนโค้ดเตลิดจนหาบั๊กไม่เจอ **เราจะมีจุดหยุดพัก (Pause & Verify) เมื่อจบแต่ละ Phase เสมอ**
เมื่อจบเฟส ผม (AI) จะมีหน้าที่เตือนและถามคุณเสมอว่า:
1. **รันโค้ดแล้วระบบล่มไหม? (Crash Check):** มี Error หน้าจอดำ หรือขึ้น Exception อะไรไหม?
2. **ได้ผลลัพธ์ตรงตามเป้าหมายไหม? (Logic Check):** เช่น ถ้าเป็นระบบตัดสต๊อก สต๊อกลดจริงไหม?
3. **ขาดตกบกพร่องอะไรไหม? (Requirement Check):** มีฟีเจอร์ไหนหรือเงื่อนไขทางธุรกิจ (Business Rule) ไหนที่เราลืมนึกถึงไปหรือเปล่า?

*(คุณสามารถเบรกผม หรือขอให้เพิ่มฟีเจอร์แทรกได้ตลอดเวลาในจุด Checkpoint นี้ครับ)*

## 🌿 2. มาตรฐาน Git Workflow (Feature Branch Pattern)

**กฎเหล็ก:** ห้ามเขียนโค้ดและ Commit ลงบนกิ่งหลัก (`main` หรือ `master`) โดยตรงเด็ดขาด!
ทุกครั้งที่เราจะเริ่มทำ "ฟีเจอร์ใหม่" (เช่น ทำระบบ Login, ทำระบบเพิ่มสินค้า) เราต้องทำตาม Flow นี้เสมอ:

1. **ดึงอัปเดตล่าสุด:** ย้ายไปกิ่งหลักและดึงโค้ดล่าสุดลงมาก่อน
   ```bash
   git checkout main
   git pull origin main
   ```
2. **สร้างกิ่งใหม่ (New Branch):** ตั้งชื่อให้สื่อถึงงานที่จะทำ
   ```bash
   git checkout -b feature/login-system
   ```
3. **ลงมือเขียนโค้ด (Coding):** (ทำตามแผนใน Roadmap)
4. **บันทึกงาน (Commit):** เมื่อเทสผ่านระดับนึงแล้ว
   ```bash
   git add .
   git commit -m "feat: สร้างระบบ Login ด้วย JWT และ HttpOnly Cookie"
   ```
5. **ส่งงานขึ้น Cloud (Push):**
   ```bash
   git push origin feature/login-system
   ```
6. **รวมโค้ด (Merge / Pull Request):** 
   เข้าไปที่ GitHub เปิด Pull Request เพื่อรวม `feature/login-system` เข้าสู่ `main`
7. **อัปเดตเครื่องตัวเอง:** กลับมากิ่งหลักและดึงโค้ดที่รวมเสร็จแล้ว
   ```bash
   git checkout main
   git pull origin main
   ```

## 🚀 3. กฎของ CI/CD (Continuous Integration / Continuous Deployment)

เพื่อให้ทำงานง่ายขึ้น เราจะใช้ระบบอัตโนมัติ (Automated) มาช่วยจัดการตอนเราเอาโค้ดขึ้น Git ครับ

*   **CI (การตรวจสอบโค้ดอัตโนมัติ):**
    *   **กฎ:** ทุกครั้งที่มีการสร้าง Pull Request ระบบจะทำการ Build โค้ด (C# และ Angular) อัตโนมัติ ถ้ามีโค้ดพิมพ์ผิด หรือ Build ไม่ผ่าน จะไม่อนุญาตให้กด Merge เข้ากิ่ง `main` เด็ดขาด!
*   **CD (การอัปเดตระบบอัตโนมัติ):**
    *   **กฎ:** ห้ามก๊อปไฟล์ไปวางบน Server เองด้วยมือ (Manual Upload) 
    *   เมื่อใดก็ตามที่โค้ดถูก Merge เข้ากิ่ง `main` สำเร็จ:
        *   **Vercel** จะดึงโค้ด `main` ไปอัปเดตหน้าเว็บ Angular ทันที
        *   **Render.com** จะดึงโค้ด `main` ไปรีสตาร์ท Backend API ทันที
