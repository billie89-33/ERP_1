# 🔄 Data Migration Guide (MongoDB ➡️ PostgreSQL)

เอกสารสรุปนี้ใช้สำหรับการเตรียมตัวและวางแผนย้ายข้อมูล (Data Migration) จากระบบฐานข้อมูลเก่าแบบ **NoSQL (MongoDB)** มายังระบบใหม่ที่เป็นแบบ **Relational (PostgreSQL / Supabase)** ในโปรเจกต์ ERP ของเรา

---

## 📋 1. สิ่งที่ต้องเตรียม (Prerequisites)

ก่อนเริ่มเขียนโค้ดย้ายข้อมูล เราต้องเตรียมทรัพยากรเหล่านี้ให้พร้อม:
*   **Connection Strings:**
    *   รหัสเชื่อมต่อ MongoDB ตัวเก่า (เพื่ออ่านข้อมูล)
    *   รหัสเชื่อมต่อ PostgreSQL ตัวใหม่ (เพื่อบันทึกข้อมูล)
*   **Library ที่จำเป็น:** ต้องติดตั้ง NuGet Package `MongoDB.Driver` ใน C# เพื่อให้โปรเจกต์ .NET 8 ของเราสามารถเข้าไปอ่านข้อมูลจาก Mongo ได้
*   **Data Dictionary (สมุดแปลภาษา):** ต้องเอาโครงสร้างข้อมูลเก่า (JSON) มาวางเทียบกับ Class (`Models`) ตัวใหม่ใน C# ว่าฟิลด์ไหน จะจับคู่กับฟิลด์ไหน

---

## ⚙️ 2. ขั้นตอนการย้ายข้อมูล (How it works)

กระบวนการย้ายข้อมูลมักจะทำเป็นสคริปต์ (Script) หรือ API พิเศษที่รันแค่ครั้งเดียว (One-off Task) โดยใช้หลักการ **ETL (Extract, Transform, Load)**:

1.  **Extract (ดูดข้อมูล):** 
    ใช้ `MongoClient` ของ C# เชื่อมต่อเข้า MongoDB และดึงข้อมูล Collection (เช่น `products`) ออกมาทั้งหมด (หรือดึงทีละล็อต) เก็บไว้ใน Memory ของ C#
2.  **Transform (แปลงร่าง):** 
    ใช้ C# (เช่น `LINQ` หรือ `foreach`) ทำการแปลงข้อมูล (Mapping) จากรูปแบบเก่า ให้กลายเป็น Entity Class ตัวใหม่ของเรา (`Product.cs`)
3.  **Load (บันทึกลงบ้านใหม่):** 
    ใช้ Entity Framework Core (`_context.Products.AddRange()`) บันทึกข้อมูลที่แปลงร่างแล้วทั้งหมดลงตารางใน PostgreSQL อย่างเป็นระเบียบ

---

## ⚠️ 3. สิ่งที่ต้องระวัง (Checklist) ก่อนดึงเข้าโปรเจกต์จริง

การย้ายจาก NoSQL มา SQL ไม่ใช่แค่ก๊อปปี้แปะ สิ่งที่คุณต้องคำนึงถึงเพื่อปรับให้เข้ากับระบบ **ERP ขายอุปกรณ์คอมพิวเตอร์** ของเรามีดังนี้:

### 💡 3.1 การแปลง Data Types (สำคัญมาก)
*   **ID Mismatch:** MongoDB ใช้ `ObjectId` (String ยาวๆ) เป็น Primary Key แต่ Postgres ของเราใช้ `Guid` (UUID) 
    *   *วิธีแก้:* ต้องสร้าง `Guid.NewGuid()` ใหม่ให้สินค้าทุกชิ้นตอนย้าย
*   **Nested JSON:** ใน Mongo คุณอาจจะเก็บข้อมูลย่อยๆ ซ้อนกันเยอะมาก
    *   *วิธีแก้:* ใน Postgres เราใช้ฟีเจอร์ `JSONB` (ซึ่งเราตั้งค่าไว้ใน `Product.Specifications`) เอาของจุกจิกจาก Mongo มายัดรวมในช่องนี้ได้เลย

### 💡 3.2 การทำ Data Cleansing (ล้างขยะ)
*   **ฟิลด์บังคับ (Required Fields):** PostgreSQL มีความเข้มงวดกว่า (Strict Schema) ถ้าระบบใหม่เราระบุว่า `Name` ห้ามเป็นค่าว่าง แต่ใน Mongo มีสินค้าบางตัวไม่มีชื่อ ระบบจะพังตอน Load ทันที
    *   *วิธีแก้:* ต้องเขียน C# เช็คเงื่อนไขตอน Transform (เช่น ถ้าไม่มีชื่อ ให้ใส่ค่า "Unknown Product")

### 💡 3.3 การปรับตัวให้เข้ากับ Business Logic ใหม่
*   **บริบทของธุรกิจเปลี่ยน:** โปรเจกต์เก่าอาจจะเป็นแค่ร้านขายของทั่วไป แต่โปรเจกต์ใหม่ของเราคือ **ERP ขายอุปกรณ์คอมพิวเตอร์**
    *   *ข้อควรพิจารณา:* สินค้าอุปกรณ์คอมพิวเตอร์มักจะมีสเปคยิบย่อยเยอะมาก (เช่น RAM, CPU, ประกันกี่ปี, สี) ซึ่งระบบใหม่ของเราได้เตรียมช่อง `Specifications` (แบบ JSON) เอาไว้แล้ว ตอนดึงข้อมูลจาก Mongo เราสามารถเขียน C# จับเอาฟิลด์รายละเอียดจุกจิกพวกนั้น ยัดรวมกันเป็นก้อน JSON แล้วเซฟลงช่อง `Specifications` ได้เลยครับ! ทำให้ฐานข้อมูลเราสะอาดและยืดหยุ่นมาก

### 💡 3.4 ปัญหาด้านประสิทธิภาพ (Performance)
*   ถ้าข้อมูลมีเป็นแสนๆ รายการ การดึงมาไว้ใน C# ทีเดียวทั้งหมดอาจจะทำให้ RAM เต็มและเซิร์ฟเวอร์ล่มได้
    *   *วิธีแก้:* ต้องเขียนโค้ดแบบ **Batch Processing** (ดูดมาทำทีละ 1,000 รายการ แล้วกด Save แล้วค่อยดูดล็อตต่อไป)
