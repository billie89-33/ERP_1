# Advanced ERP Concepts (Precautions & Data Structures)

## ⚠️ 1. ข้อควรระวังระดับ Enterprise (สิ่งที่พลาดไม่ได้ใน ERP)

### 1.1 Database Transactions (กฏ All or Nothing)
**ปัญหา:** สมมติพนักงานกด "ยืนยันรับของ" ระบบต้องทำ 2 อย่างคือ 1) เพิ่มสต๊อก และ 2) สร้างประวัติรับเข้า... ถ้าทำข้อ 1 เสร็จ แต่ไฟดับก่อนทำข้อ 2 ข้อมูลบัญชีจะพังทันที!
**ทางแก้:** ต้องใช้ระบบ **Transaction** ควบคู่กับ **`try/catch`** เสมอ:
*   ในบล็อก `try { ... }` เราจะสั่งทำงานทั้ง 2 ข้อ และสั่ง `Commit`
*   ในบล็อก `catch (Exception ex) { ... }` เราจะดักจับ Error และสั่ง **`Rollback`** ทันที เพื่อยกเลิกสิ่งที่ทำไปแล้วทั้งหมด คืนความสมดุลให้ระบบบัญชี

### 1.2 Race Conditions (ปัญหาแย่งกันซื้อสต๊อกชิ้นสุดท้าย)
**ปัญหา:** มีสินค้าเหลือ 1 ชิ้น พนักงานขาย A และ B กดสร้างบิลขาย "พร้อมกันในเสี้ยววินาที" ถ้าเช็คสต๊อกไม่ดี ระบบอาจจะยอมให้ขายทั้งคู่ กลายเป็นสต๊อกติดลบ (-1)
**ทางแก้:** ต้องทำ **Concurrency Control** (ปกติใช้ Optimistic Concurrency โดยเพิ่มคอลัมน์ `RowVersion` ใน Database) เพื่อล็อกไม่ให้มีการแก้ไขข้อมูลที่กำลังถูกคนอื่นแก้ไขอยู่ครับ

### 1.3 Audit Trail (ประวัติกรรม)
**ปัญหา:** สต๊อกหาย หาคนทำผิดไม่ได้
**ทางแก้:** ทุกการแก้ไข (Update/Delete) ใน ERP ที่ดี จะต้องมีการบันทึกเสมอว่า "ใคร (UserId) ทำอะไร (Action) เปลี่ยนจากค่าเก่าเป็นค่าใหม่เมื่อไหร่ (Timestamp)"

## 🧠 2. การประยุกต์ใช้ Data Structure ใน ERP

ความรู้ Data Structure ไม่ได้มีไว้แค่สอบสัมภาษณ์ครับ แต่มันใช้แก้ปัญหา Performance ใน ERP ได้จริง:

### 1. Hash Table / Dictionary `O(1)`
*   **ใช้ทำอะไร:** ใช้ทำ Caching หรือ Lookups เพื่อลดภาระ Database
*   **ตัวอย่าง:** แทนที่จะให้ C# ค้นหาราคาสินค้าใน Database 1,000 ครั้ง เราดึงสินค้าทั้งหมดมาเก็บใน `Dictionary<Guid, Product>` (โดยให้ Key คือ ProductId) เวลาจะหาราคาสินค้า ก็แค่เรียก `dict[productId]` ข้อมูลจะโผล่มาทันทีแบบ `O(1)` เร็วปรู๊ดปร๊าดเลยครับ

### 2. Tree (แผนผังต้นไม้)
*   **ใช้ทำอะไร:** ใช้กับข้อมูลที่มีลักษณะเป็นลำดับชั้น (Hierarchy)
*   **ตัวอย่าง 1:** **หมวดหมู่สินค้า (Categories)** เช่น เสื้อผ้า -> เสื้อผู้ชาย -> เสื้อยืด (มี ParentId, Children) 
*   **ตัวอย่าง 2:** **โครงสร้างองค์กร (Org Chart)** ผู้จัดการ -> หัวหน้าทีม -> พนักงาน เพื่อเอาไว้เช็คสิทธิ์การอนุมัติใบสั่งซื้อ (Manager Approve)

### 3. Queue (คิว / FIFO)
*   **ใช้ทำอะไร:** จัดการงานที่ต้องใช้เวลาประมวลผลนาน (Background Jobs) เพื่อไม่ให้หน้าเว็บค้าง
*   **ตัวอย่าง:** การกด "สร้าง Report บัญชีย้อนหลัง 1 ปี" (ใช้เวลา 5 นาที) เราจะไม่ให้ Angular หมุนติ้วๆ รอ 5 นาทีครับ แต่เราจะเอาคำสั่งนี้โยนเข้า **Queue** (เช่น RabbitMQ หรือ BackgroundService) แล้วให้ผู้ใช้ไปทำงานอื่นต่อ พอ Queue ปั่น Report เสร็จ ค่อยส่งแจ้งเตือน (Notification) ไปบอกผู้ใช้ครับ

### 4. Stack (LIFO)
*   **ใช้ทำอะไร:** ระบบ "Undo / Redo"
*   **ตัวอย่าง:** เผื่อพนักงานคีย์บิลผิด พิมพ์ตัวเลขผิด สามารถกด Ctrl+Z ย้อนกลับค่าฟอร์มก่อนหน้าได้ (เก็บ State ไว้ใน Stack ฝั่ง Angular)
